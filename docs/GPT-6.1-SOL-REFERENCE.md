# gpt-6.1-sol 参考采集与验证

2026-10-20，用户明确授权官方采样、扩展指纹库并更新本机插件。版本 0.4.3。

## 来源与隔离

- 采样目标为 CCSwitch 中的 `OpenAI Official`，无 managed account，跟随当前 Codex home 的原生 ChatGPT 登录。
- 原生 Codex 选择 `openai` 契约，通过私有 loopback 网关的显式 provider 路径，固定转发到 `https://chatgpt.com/backend-api/codex/`。未使用 API2 参考，也未读取认证文件、复制登录凭据或改 CCSwitch 全局默认卡。
- 模型为 `gpt-6.1-sol`，推理强度 max，服务层 Standard，Codex CLI 0.163.0。每条是独立一次性原生会话，只允许单次文本回答，工具尝试拒绝。
- 每条保存模型设置、官方配置摘要、原生 thread ID、HTTP 200、完整 `response.completed` 成功回执及 token 用量。回执证明本地选路，不证明服务内部模型身份。

## 参考数据

完整沿用 12 种环境，每种 3 条任务，共 36 条独立回答。中文、英文、JSON 展示格式以及 system/user 前缀均由现有 `challenge_suite.py` 提供。任务 ID 与旧库 `query-01..36` 对齐，支持按任务分组交叉验证。

36 条均满足官方回执、无重复输出、规则模式检查和数量比 [0.8, 1.2]；本批所有条目的数量恰等于要求，合计 10,584 个整数。数据已合并到 `data/gpt_reference.jsonl`；统一库共 19 模型、684 条参考，完整覆盖 12 种环境。

一条请求发生原生传输重试。采集器先读到了旧失败回执并停止分段，原始最终输出已保存；待真实成功回执落盘后，以同一 thread/配置/目标/时间范围重新验证原样本，不新增推理、不伪造回执。采集器现等待最终回执，避免前一失败尝试抢先终止验证。

## 插件判定口径：已知混淆组（2026-10-21）

实际切换验证中，官方 `gpt-6.1-sol` 目标探针被判为 `gpt-6-astra`（0.4998），预期权重仅 0.0251，结果 `inconclusive`，切换失败。这与上表 zh-3 / en-2 属于同一类型。按单条交叉验证结果，官方同模型目标验证约一半会因此失败；主渠道监测也会产生同类误报暂停。

处理方式：在 `codex-plugin/modeltrace-guard/assets/confusable-groups.json` 登记 `{gpt-6.1-sol, gpt-6-astra}`。第一候选与预期同组、且组内合计权重 ≥ 0.5 时判为 `compatible`，并在样本上标注 `confusableGroup`；不算不一致，不暂停，也可作为目标验证的指纹条件。上述 6 条留出样本按此口径均不再误报。组外候选（例如 `gpt-5.6-luna` 0.986）的判定不变。

- 口径变化：组内互判从「不一致 / 无法判定」改为「兼容（同组）」。这两个模型之间的真实替换将检测不到，与评分器本身的区分能力一致。
- 绑定条件：分组文件记录了指纹库 SHA-256。指纹库重建后分组自动失效，判定退回严格口径；`tests/confusable-groups.test.mjs` 会失败，提示重新验证。
- 未改动：样本标签、评分算法、概率阈值和指纹库本身。未为提高数字而修改样本标签、阈值、评分算法或把留出样本回灌训练。库与插件已更新，当前会话未自动启用监测。更多推理强度、语言、长上下文及真实 frozen-fork 误报率仍未校准。
